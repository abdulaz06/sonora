# Decisions

Short ADR-style records. Newest last.

## D1 — One analysis crate for desktop and browser
**Context:** the renderer needs the same frames in the Tauri app and in a plain browser (dev page, verification harness, future web build).
**Decision:** `crates/sonora-dsp` holds the whole pipeline with no platform code. `src-tauri` feeds it from WASAPI; `crates/sonora-dsp-wasm` wraps it with wasm-bindgen and returns frames as JSON (same serde_json as the Tauri event payload, so the shape is identical by construction). `scripts/check-parity.mjs` compares native vs WASM frame by frame; the only differences are single rounding quanta (1e-3) caused by MSVC vs wasm libm.
**Consequence:** a Cargo workspace at the repo root; build output moves to `/target`. `npm run build` now needs `wasm-pack`.

## D2 — Hop derived from sample rate
Frames are produced every `round(sample_rate / 60)` samples in both builds (was a fixed 735). Keeps the analysis at 60 Hz of audio time at 48 kHz too, and makes offline rendering exact.

## D3 — Per-band adaptive normalisation in the mapping layer
**Context:** with raw band RMS, high/air sat ~100× below bass, so high hits never fired, mid presence stayed near 0 and intensity saturated on loud masters.
**Decision:** `norm.rs` divides each band by a slowly decaying running peak (30 s half-life) with an absolute floor; presence, hits and the beat ODF use the normalised values. Intensity mixes loudness relative to the track's own recent peak (70%) with absolute loudness (30%). Raw `bands` in the frame are unchanged, so classic styles and the debug overlay are unaffected.

## D4 — Beat tracker rewrite
Autocorrelation of a smoothed ODF with a log-Gaussian tempo prior (120 BPM, 0.9 octave) and a half-tempo harmonic term; phase is a free-running oscillator corrected toward ODF peaks (PLL) instead of hard resets. Locks 124 BPM house exactly; reads the 140 half-time track as 70 in its drop (a valid half-time reading).

## D5 — Event layer in TypeScript, per analysis frame
Runs on every analysis frame (not per render frame) so results are deterministic for a given input and identical in desktop and browser. Drum activity for drop/breakdown uses sub-bass presence + bass-hit activity rather than the 60–250 Hz band, which pads leak into. Drops require a sharp jump (<0.9 s) armed by a build, a short gap inside music, or a long kick-less stretch; long silences are track changes, not drops.

## D6 — Two post pipelines
Art styles use `ArtPost` (render scale, threshold mip bloom, ACES or no tonemap). Classic styles keep the legacy pipeline so their look does not change.

## D7 — Flow Ink world: periodic fluid domain
The sim runs on a torus (REPEAT textures) 4 world units across, so the camera can drift forever with no walls. Depth view fog ends at ~3.4 units so a tile never repeats on screen.

## D8 — Flow Ink dye stores palette slots, not colours
Dye channels are ink A, ink B, sparkle, lift. Colour is applied at render time, so palette changes and Auto Drift recolour ink already on screen, and duotone/paper variants are just different shading.

## D9 — Directional jets instead of radial explosions
A radial splat is pure divergence and the pressure projection deletes it (only swirl survives, giving cartoon spirals). Bass hits and drops inject directional jets, which roll up into vortex pairs (ink "mushrooms"); dye goes in as broken rings with thin tendrils. A subtractive floor decay clears faint haze so quiet passages keep negative space.

## D10 — Verification in audio time
`npm run verify` renders in a real browser (system Edge, real GPU) and advances audio and visuals together with a fixed dt, so screenshots are deterministic and independent of frame rate. A separate real-time pass measures FPS at the drop.

## D11 — Auto Drift on by default
DOCS/16 lists palette drift under "never static"; drift defaults on with a 3-minute cycle and can be turned off or slowed to 10 minutes in settings.

## D12 — Local working notes stay untracked
The local working-notes file and tool settings are listed in `.gitignore`; the project-facing docs live in `DOCS/` and `README.md`.

## D13 — Beat response bypasses the solver
**Context:** Flow Ink 2.0 looked good but lost v0.1's lock to the beat. Measured: only 9% of kicks produced a visible change in Flat. The DSP was fine (95–100% of kicks detected, ~30 ms); the incompressible solver needs hundreds of ms to turn a splat into motion, and hits added no brightness.
**Decision:** three frame-accurate layers keyed to the bass-hit envelope: (1) dye-only "kicks", a divergent, lopsided outward push applied to ink advection but not to the velocity field (so the pressure solve cannot cancel it); (2) an "energy" dye channel injected by hits that glows past 1.0 and decays in ~150 ms; (3) a global ink-brightness pulse. Responsiveness scales (1) and (3).
**Result:** `npm run verify -- --sync`: Ink Flat/Depth and Marble see 100% of kicks with 40–66% luminance jumps at 33–60 ms; Sumi (paper) 43–90% on the luminance metric, which undersells motion on paper.

## D14 — v0.1 palettes restored; drift off by default
The first seven palettes are v0.1's, in v0.1 order, so names and saved indices mean the same colours; four duotones follow. Flow Ink maps ink A = primary, ink B = accent, sparkle = highlight, as v0.1 did. Auto Drift (renamed "Colour drift") is off by default; settings v3 resets older saves that had it on.

## D15 — User camera for Depth
`CameraView` = height, tilt, curve (−1 bowl … +1 planet). Presets: Glide, Horizon, Planet, Valley, Overhead. Curvature is applied in the ground vertex shader around the camera (−k·d²) with matching normals; fog grows with altitude, and the sky's horizon band brightens with planet curvature (atmosphere). Mouse: drag turns/tilts (pans in Flat), wheel changes height (zooms in Flat), double-click snaps to the nearest preset, `C` cycles presets.

## D16 — Sync metric in the harness
`--sync` renders 12 s around the drop and scores, per known kick (exported by the generator), the largest relative luminance change within 133 ms. It is the regression test for "music and visuals in sync".

## D17 — Desktop capture recovers by itself
**Context:** plugging speakers into the 3.5 mm jack could stop the visuals while music kept playing. cpal reported the stream error but nothing reopened capture, and when the endpoint name stays the same (Realtek jack re-routing) the default-device poll saw no change. WASAPI loopback also delivers no packets during silence, so the renderer froze on its last frame.
**Decision:** a stream error flags the capture for reopen; a watchdog reopens after 3 s without samples (harmless during silence, quiet when it is the same device, keeps analysis state); after 120 ms without samples the pipeline analyses silence at the normal hop rate so visuals decay instead of freezing.

## D18 — Web audio sources: tab first, health-checked
**Context:** Chromium binds whole-computer (system) audio sharing to the output device active when sharing started; changing speakers/headphones silences it and a new capture needs a click. Tab audio follows the tab. The old source dropdown also could not re-select the same option, so re-sharing silently did nothing.
**Decision:** a source chooser with plain-language options (Browser tab — recommended, Whole computer, Microphone/line-in with device list, Audio file, Test tracks), a status chip with a live level meter, and a banner with one-click Reconnect when sharing stops or when a device change is followed by silence while music had been playing. Captures request raw audio (no echo cancellation / noise suppression / auto-gain, which Chromium otherwise applies). Microphones re-acquire automatically. The last capture type is remembered for a one-click reconnect on the next visit.

## D19 — Global flash guard (WCAG 2.3.1)
**Context:** the art styles use inversion cuts (Silk, Turing), glitch strobes (Mosh) and drop flashes (Warp, Fractal). Several can coincide with a beat pulse.
**Decision:** `FlashGuard` in the renderer, two layers. (1) `ctx.flash.request()` before any deliberate flash: at most 3 per rolling second with a 0.25 s minimum gap; denied requests simply skip the effect. (2) An async GPU luminance probe (the composite re-run into a 32×18 target, read back through a PBO + fence, about a frame late) counts rises larger than 0.1 in mean luminance from any source. If 3 happen within a second, damping engages for 1.2 s and the composite scales each frame toward the running mean so further swings stay small. The debug overlay shows `flashes n/s`.

## D20 — Shared GL toolkit for art styles
`src/styles/shared/gl.ts`: render targets (MRT), ping-pong pairs, `//#include` shader chunks, automatic uniform maps, and a uniform setter that uses each uniform's declared GL type (a boolean sent to a float uniform once rendered Mosh black). `shared/noise.glsl` holds pcg hashes, simplex noise, curl and hue rotation.

## D21 — Mosh tunnel is analytic, the feedback is only the mosh
**Context:** a classic zoom-feedback buffer (each frame resamples the last one, zoomed) blurs to mush within a second because bilinear resampling compounds.
**Decision:** the nested-frame tunnel is computed analytically every frame (Droste mapping: log of Chebyshev distance gives the level, each level samples its own patch of the procedural seed). Beats push the tunnel back one level over 0.18 s. The previous frame is used only for the datamosh layer: luminance displacement, pixel-sort smear, RGB-split glitch blocks, scanline tears and the drop freeze. Seeds are procedural (concrete/asphalt with aggregate, cracks and worn paint marks; or Sonora geometry and the spectrum), no photos.

## D22 — Turing text seeding
`trackChange` events carrying a title (media session, the dev page's **Seed text** button, files played on the dev page, harness `--text`) render the title into a mask canvas (Inter 500, about 85% of the view wide, wrapped into the periodic grid). For 6 s the glyph interiors are held at the activator seed and a 5-cell moat around them is held empty, so the word grows readable stripes that the maze then slowly reclaims.

## D23 — Starry Night keeps its night/warm contrast under any palette
The look depends on blue-night vs warm-star contrast. Night colours rotate by the palette primary's hue offset from 220°, warm colours by a quarter of that, so palettes and Colour drift change the mood without turning the stars the same colour as the sky.

## D24 — Fractal: Mandelbox flight with a CPU-mirrored planner and temporal upscale
**Decision:** a Mandelbox (Voyage: scale 2.9, Kaleido: 2.6 with rounder folds), chosen after measuring the free space inside candidate scales: negative scales were almost solid at a flyable clearance. A JS copy of the distance estimator lays waypoints ahead of the camera so every point of each segment keeps at least ¼ of the preferred clearance, scoring candidates by turn smoothness and closeness to the preferred clearance; the camera rides a Catmull-Rom spline through them at a speed measured in clearances per second. The march runs at half the scene resolution (¾ on High) with a Halton jitter; `resolve.frag` reprojects the previous frame through the hit depth, clamps it to the current neighbourhood and blends. Brightening is accepted immediately, so bass pulses land on the hit frame (sync 100% of kicks, ~62 ms). The step budget adapts to the measured frame time. Kaleido folds the resolved image into 5–8 mirrored wedges; drops change the wedge count.

## D25 — Responsiveness drives motion, never brightness
**Context:** at Punchy, Ink flickered and blew out in the live app: its beat pulse scaled ink brightness by up to 2x (plus an exposure bump), and the Punchy intensity follower (5 ms / 50 ms) passed frame-to-frame noise from real music straight into brightness-linked values in several styles.
**Decision:** the Responsiveness slider only scales motion (kick strength, plucks, zoom punches, beat pushes). Brightness and density use `intensityGlow`, a fixed slow follower (120 ms / 700 ms). Punchy becomes 15 ms / 120 ms. Hit brightening has fixed headroom per style and no global exposure bump.

## D26 — Hue-preserving tonemap and auto exposure
**Context:** saturated palette colours above 1.0 (Ocean on Ink, Silk cores, Warp at speed) went white under per-channel ACES.
**Decision:** the composite tonemaps the brightest channel and scales the colour with it (hue and saturation kept), blended 25% with per-channel ACES for the filmic look; only extreme highlights roll to white. A slow auto exposure (0.8 s down, 4 s up, floor 0.5) uses the luminance probe's mean and blown-out fraction for filmic scenes. Harness `--flicker` reports swings/s, jitter and blown-out pixels; `dense-128` is a loud, busy test track because the sparse tracks under-represented real music.

## D27 — v1.0 lineup
**Decision:** Ink (Glow, Marble, Sumi), Silk, Wisp, Warp, Voyage, Mosh. Silk, Wisp and Warp are separate styles sharing the particle engine. Lumen, Starry Night, Turing and Kaleido (as a look) were removed after review; Kaleido's mirror became a Voyage drop effect. Settings v4 migrates saved choices to the nearest successor.

## D28 — Ink: one kick, one splash
**Context:** Ink 2.0's dye lasted ~14 s, so the field filled up and new splashes were swallowed; the original Flow Ink faded in ~1 s and read as tightly synced.
**Decision:** Glow/Sumi dye decays in ~1-2 s (longer when loud), inflow is a drizzle, bass splats are larger and land in view, turbulence is lower between hits; breakdowns let ink linger (decay 0.18/s) so they read calm rather than empty. Marble keeps its persistent marbling.

## D29 — Silk: beat motion in the display pass
**Context:** displacing particles on the beat barely showed: the trail buffer keeps 84% of the previous frame, so a moved thread appears as a faint echo next to its old trace.
**Decision:** the beat zoom punch, the radial snap and the ripple ring are applied in the display pass, warping the whole image (trails included) on the frame of the hit; a smaller per-thread "pluck" ripple stays in the particle draw. Builds gather threads into a knot; drops burst them into an eight-spoke starburst for ~5 s.

## D30 — Mosh: a palette-mapped, reversing vortex
**Decision:** Signal patterns are luminance-only and coloured through a gradient map (background → primary → highlight), which keeps every palette coherent. Nested frames rotate against each other (twist rides intensity, flips on drops), the shape morphs between rectangle, circle and diamond, and direction is musical: each beat pushes a step, drops reverse every bar, builds go in, breakdowns drift out.

## D31 — Voyage: cylinder backdrop and camera-relative bending
**Decision:** rays leaving the Mandelbox continue into a cylinder (radius 36) whose inner wall is tiled with mini Mandelboxes sliced flush with the wall, so their carved interiors face inward: an endless world curving overhead. Space is bent by a slow sine warp (mirrored in the CPU planner, with a distance-bound correction and a camera safety push) and by a corkscrew about the view axis that is zero at the camera and kicks on beats. Drops fold the screen into a Kaleido mirror for ~3 s.

## D32 — Silk: no beat zoom or ripple
**Context:** on bass-heavy songs the display-pass zoom punch and ripple ring (D29) fired constantly and made Silk look worse.
**Decision:** removed, together with the per-thread pluck. Silk's beat response is the on-hit thread brightening and shockwaves; the build-knot / drop-starburst moment stays. Supersedes D29.

## D33 — Wisp has its own fixed view
**Context:** Wisp came back blank on a second visit: a fresh instance placed its flames near its world origin while the shared camera had drifted (or been dragged) far away.
**Decision:** Wisp ignores the camera centre and rotation (fixed centre, no pan or drag); only the zoom (view height) follows the camera.

## D34 — Ink: beat anchors
**Context:** kicks landed at random spots, so even though every kick produced a splash, the result looked scattered and the sync was hard to see.
**Decision:** 3-4 anchor points per layout form a stable off-centre composition that drifts slowly. Normal kicks bloom from the anchors in turn; every fourth kick and big hits bloom from all of them; each anchor keeps its ink colour and spin; mids are satellites and highs sparkle around anchors; random jets removed. Drops bloom every anchor and move to a new layout (also at build / breakdown). Loud sections fade faster (0.75/s) so each pulse clears.

## D35 — Voyage: the world stays still, the camera moves
**Decision:** the beat corkscrew, the bass fold breath and the Kaleido drop fold are gone. Beats roll the camera (alternating sway) and breathe the field of view; drops surge with a wide-angle punch and one eased barrel roll. The tiled cylinder backdrop (D31) read as a thick dome; it is replaced by a thin landscape drawn analytically on the inside of a giant cylinder (radius 70, floor 9 units below the fractal): patchwork fields with crop rows, forests, ridges, rivers and fractal-slice cities, palette-tinted earth, rising into haze with the sun at the axis end. Supersedes D31's backdrop and beat folds.

## D36 — Mosh removed
After two rebuilds Mosh still did not hold up; removed. Saved settings move to Ink.

## D37 — Voyage: only the backdrop is stable
"Stable world" (D35) meant the backdrop only. The fractal's bass fold breath and alternating beat corkscrew are back (fractal space only); the landscape never moves on beats.

## D38 — Voyage: wide shots and a detailed curved world
**Decision:** breakdowns (or a calm moment after 60 s without one) steer the flight planner outward with a goal bias that relaxes its bound, so the camera flies out through an opening (cut after 12 s if no way out); it then eases into a slow drift outside the fractal looking down the cylinder axis. The drop dives back in (handover hidden in the dive and barrel roll); idle-triggered shots return after ~15 s. The landscape is analytic: strips of rectangular fields with crop rows and hedges, grass, forests, rock/snow ridges, shores, rippling water with sky reflection and sun glint, and clustered 3D tower blocks raymarched in a thin layer above the ground (cheap masks inside that loop; step budget per quality). Vista frames ~4–8 ms at 1080p Medium. NaN guards in the march and the temporal resolve.

## D39 — Warp: slow-motion sections
Breakdowns, and intros while intensity is still low, drift at 10% pace (streaks shrink to near-hanging stars); regular pace once the beat is in; builds accelerate; drops jump. Pace changes settle in ~2 s.

## D40 — Voyage backdrops: Void, City, Ocean
**Decision:** three looks. **Void** (default): a dark sky tinted by the palette accent with a faint nebula and three layers of twinkling stars. **City:** the curved world, rebuilt in 3D — its large-scale layout (terrain height, rivers/lakes with fixed-width shores, city districts kept off banks and mountains, forests, a dry featured district overhead) is baked once into a 2048² texture wrapped round the cylinder; a short raymarch then finds real terrain relief with rock crags, tree canopies and street-grid blocks of 2x2 lots (setback towers, parks, varied roofs, lit windows), with fine procedural ground detail on top. Lit from the axis as in a habitat. **Ocean:** the cylinder is all sea with four swell trains rolling down the axis, chop, backlit crests, foam and glints. World radius 30 so the far side is close. Backdrop code in `backdrop.glsl`, bake in `landbake.frag`.

## D41 — Voyage wide shots follow the music
**Decision:** shots per backdrop — Void circles the fractal in the stars, Ocean looks down the axis, City alternates the axis view and an angled look up at the hanging city. A shot ends as soon as the music picks up (intensity above its starting level, a build or drop, or the breakdown ending), capped at 10 s (8 s idle-triggered). The camera eases back and replays its recorded exit path in reverse (collision-free, smooth), then the planner resumes from there (`FlightPath.restartAt`). A drop while out still dives straight in. Wide shots render at a higher march scale (0.7 Medium, 1.0 High) without the chromatic fringe.

## D42 — Depth views for Silk and Wisp
**Decision:** both get a Depth/Flat toggle with **Flat as the default** (Ink keeps Depth as its default). The Flat path is untouched: Depth compiles separate draw and display programs (`#define DEPTH`), and Flat renders are pixel-identical to before. In Depth the 2D particle simulation lies on the ground plane of the shared 3D camera (scaled up: 2.4 ground units per sim unit for Silk, 1.3 for Wisp), centred just ahead of where the camera looks; emitters and shockwaves are placed on the ground under the lower part of the screen. Each particle gets a height and is drawn in perspective with the camera's fog and curvature, so the camera presets, drag and scroll all apply. **Silk:** ribbons float as thin sheets whose height rolls smoothly with position (noise), so they rise and dip like silk in the air; dust floats higher as stars. **Wisp:** each flame flies at its own slowly changing height; smoke keeps the height its flame had when it was shed and drifts upward; the flames circle a point nearer the camera, and the CPU projects them for the flame pass. Wisp smoke fades faster in Depth (0.955 per frame) so camera motion doesn't smear it. Beat reactions (shockwaves, rings, the drop knot/starburst and inversion cut) are the same simulation in both views.

## D43 — Ink: kicks land like v0.1 (stamp, light, stream off)
**Why:** Ink measured 100% sync but no longer felt synced. Frame-by-frame study of a v0.1 recording (kicks found in its audio): on each kick the centre jumped ~2.8x in brightness within 1-2 frames and faded steadily over exactly one beat; the kick lit ink already there instead of pushing it; shapes were broad sheets that held for seconds because v0.1's flow was a nearly steady curl field (ink streamed along standing streamlines); kicks landed at random spots near the centre. Ink 2.x instead blasted each splash outward on the frame it appeared and shoved its neighbours, so shapes never read.
**Decision:** (all looks, both views) one kick per beat (re-armed when the hit falls); a solid shape at a random spot inside a slowly wandering focus zone near the centre (jumps on drops and section changes; every 4th kick blooms bigger at its heart); a beat light carried in the dye's energy channel, so it lights the ink and streams off with it, fading with a tempo-tied time constant (0.42 beat); a brief hold of the flow under a fresh shape; no outward kicks. Glow and Sumi use a quasi-steady flow (strong damping with a matching curl-noise stir) so ink forms standing sheets while the field keeps evolving (no v0.1 repetition), plus v0.1's ambient drizzle done in the dye pass. Bright ink gets less light and a soft ceiling stops blow-out. Anchors (D34) removed. `scripts/beat-strip.mjs` renders a 50 ms frame strip across two beats for comparisons like this.

## D44 — Flat zoom apart from the Depth camera; Planet preset
Flat views get a saved Zoom slider (0.6-1.6, default in the middle, labelled, double-click resets) that the wheel drives; Depth keeps height/tilt/curve. Nothing in Depth changes Flat zoom. Planet preset is now height 0.6, tilt 0.75, curve 1 (looks further down at a stronger curve, so the sphere reads).

## D45 — Wisp Depth looks: Ground and Tunnel
**Ground:** the calm Depth view (presets, drag, scroll) gains depth cues without the planet look: each flame lights the dark ground beneath it like a lantern (ray-traced per pixel against the curved ground, physically-shaped falloff so height and distance read), and ~14% of the particles float as embers at all heights that glow as a flame passes (parallax as the camera glides). **Tunnel:** a chase camera rides behind the three flames down an endless, winding tunnel (own camera, presets hidden). The tunnel is stateless: wall particles sit on lanes running down the tube and on rings, placed from their id and the distance travelled; trails read a 60 Hz history of each flame's path. Pace follows the song like Warp (cruise on the slow intensity follower, section multipliers, builds accelerate, the drop bursts forward); each kick sends a ring of light racing down the walls, flares the flames and sways the camera roll. Looks are Depth-only; Flat Wisp is unchanged.

## D46 — Ink moves like v0.1 Flow Ink (supersedes D43)
**Why:** D43 still felt wrong. Abdul recorded current Ink Flat on the same song as his v0.1 recording; aligned by audio cross-correlation (2.69 s) and measured frame by frame, 73% of current Ink's frame-to-frame change was fine-detail shimmer (flecks, streaks, texture moving everywhere) against 34% in v0.1, whose change is in large shapes (a kick lights a region; sheet edges glide). Hits drowned in constant busy motion; still frames could not show it, difference images and the large-vs-fine split did.
**Decision:** all three looks use v0.1's motion model (git e094ede) on the periodic world: the velocity is a curl-noise field (no momentum, pressure or vorticity), fewer noise cells across x than y (v0.1's square sim was stretched over a wide screen), speed calibrated to the recording (block-matched ink speed 0.41 vs 0.38 screen heights/s), soft single-step advection at ~330 texels per screen, v0.1 fade rates and caps. Hits are v0.1's impulses: bass a big soft blob near the centre at a random angle with a one-frame outward push, mids and highs smaller blobs anywhere; each lands over three frames, front-loaded (35% on the frame of the hit), the drop over six. The field evolves slowly and jumps on drops and track changes (no v0.1 repetition). Removed: the fine noise layer (combed scalloped fronts with our noise), the ambient drizzle (floods with our analysis' higher mid presence), D43's zone/hold/beat light, Glow's grain (world-locked, it slid as shimmer). Looks change only drawing and drops: Glow linear (v0.1) shading; Sumi small round drops with a soft rim and no wide skirt (a soft blob's skirt greyed the whole page = flicker), no beat pulse; Marble a renewing marbled field with the same motion and hits, its gentle 0.28 beat brightening kept, a slightly softer dither. Glow fine share 42% (gate ≤45%).

## D47 — Flicker and motion gates; flash guard fixes
**Why:** `--flicker` reported Sumi at 0 swings while it visibly flickered. Two causes: the check (and the app's flash guard) only counted brightening, so dark flashes on paper were invisible; and the guard's exposure hold multiplied the frame by running/current luminance measured a frame late (0.4–1.6×), an unstable loop that flipped paper between white and grey frame to frame.
**Decision:** the flash guard counts changes either way; its hold is smoothed (0.25 s) and bounded (0.8–1.25) so it cannot ring. `verify --flicker` counts swings either way and gates: swings ≤2.5/s (WCAG 3/s; v0.1 measures 3.1/s on its recording, and its hits are what Ink should do), largest one-frame change of mean luminance ≤0.12 (per-hit rule ~0.1; v0.1 0.11), blown-out ≤6%. `scripts/motion-check.py` gates a rendered sequence (or a recording): fine-detail share of motion ≤45% (v0.1 34%) and background (night / paper) step p99 ≤0.02 (v0.1 0.003; round-6 Sumi 0.58). `--sync` also reports regional sync (largest change of an 8×5 region within 133 ms ≥15%): a drop of ink on paper is plainly seen but barely moves the screen mean. Private real songs can be harness tracks (`scripts/add-local-track.py`, git-ignored `test-audio/local/`).

## D48 — Settings per style
Every style keeps its own palette, custom hue, colour drift and drift speed, responsiveness, Depth camera and Flat zoom (settings v5, `styles` map; the top-level fields mirror the active style). Old saves seed every style from the shared values once. "Same colours for every style" shares just the colour settings. Quality and frame-rate cap stay global (they are about the machine). Styles can override camera presets: Silk's Planet is height 0.9, tilt 0.73, curve 1 (its threads reach well past the frame).

## D49 — Wisp Depth: flames stay in view, embers react
Flames that leave the screen (or drift past 1.6 orbit radii) turn hard for home and speed up; past 3 radii they are pulled straight back. Embers each drift on their own phase of the field with their own heading (no shared pattern), are dragged along and spun around the flames' paths, ride bass smoke rings outward and stir on kicks. Depth's drop flare and ring smoke are gentler (near the camera they blew out).


## D50 — Home menu is the front door; the engine pauses there
Every launch opens on a home menu ("Open straight into my last visual" is a setting, off by default). The menu shows only pre-rendered media: the render loop is stopped (`renderer.stop()`) and analysis keeps running so meters stay live. Choosing a style expands its thumbnail to full screen and dissolves into the live render, which starts underneath. Esc or Menu returns. Five style cards form a film strip: the focused card opens wide and plays its loop; captions sit below the pictures (no text over imagery, no gradient scrims).

## D51 — Design system
Tokens, components and one motion family (expo-out / quint in-out, 140–1100 ms, reduced motion respected) live in `src/ui/ds/`. Fonts are bundled: Inter variable with its optical-size axis (opsz 32 is Inter Display, used for headlines) and IBM Plex Mono 400/500/600, OFL licences beside the files. Components return plain elements; screens are in `src/ui/screens/`. The controller became UI-free: screens call its setters and subscribe to changes.

## D52 — Media pipeline
`npm run media` renders every thumbnail and loop from the engine in audio time (harness, real GPU), from a plan in `scripts/media-plan.mjs` with candidate times, a curated pick and loop length. Masters and frames go to the git-ignored `media/`; shipped: WebP stills (1280/640, palettes 480) and VP9 WebM loops (960×540, 30 fps, seamless by blending the frames after the end over the start, capped at ~1.35 MB) in `src/assets/media/` with `manifest.json` (source track, time, palette, camera per asset) for reuse by the landing page. Voyage look thumbnails are the natural breakdown vistas (Void: the fractal in the stars, City: the curved world and hanging city, Ocean: the swells), so no engine change was needed. Shipped total 12.7 MB. While UI work is in progress the pipeline runs from a git worktree pinned to the engine commit (the harness server now also runs without file watching / HMR).

## D53 — Settings v6, first run
v6 adds open-last-visual, onboarded, launches, now playing (show, corner, controls), Set Mode (on, include list, minimum interval, palettes), fullscreen display, update checks and the pinned device's display name. Saves from before v6 count as onboarded (they have used Sonora) and keep every per-style value; "Show the intro again" is in Settings › System.

## D54 — Set Mode
Switches on `trackChange` (crossfade) and, with 60% chance, on a drop that follows a build of 8 s or more (hard cut on the drop frame through `renderer.requestFlash()`, crossfade if refused); a breakdown also switches after three intervals without one (continuous mixes). Choice: a 20 s rolling picture of intensity, four-on-the-floor, beat confidence, ambient-free rhythm and BPM gives an energy 0–1, matched against each piece's place on the calm→driving scale with a Gaussian weight and random jitter; the last three picks and the current piece are excluded. ## D61 — Frame cap matches the display; even divisor caps
**Why:** the cap defaulted to 60 on Abdul's 165 Hz display. No offered cap (30/60/90/120/144) divides 165, so frames were held for 3-3-3-2 refreshes and smooth motion juddered; "max" visibly helped.
**Decision:** the default is "match display" (render on every refresh). The renderer measures the refresh from rAF intervals (mean of the intervals within 20% of the 10th percentile of the last 120: robust to slow frames, no jitter bias; a short probe at startup covers the menu, where the loop is paused) instead of trusting a number. Offered: match, the refresh's whole-number divisors (every 2nd and 3rd refresh: 165 → 82.5, 55), then 30/60/120/144 where they're below the refresh, marked "may stutter on this display" in the (i) text when they don't divide it. Divisor caps are stored as −k (every k-th refresh), so they stay even on another monitor; a fixed cap that happens to divide the refresh also paces every k-th refresh; others keep the due-time pacing (average right, spacing alternates). Settings v7: a saved 60 from before v7 (the old default) becomes match; every other explicit choice is kept (migration test). Auto quality judges frame time against the paced interval. "Unlimited" is not offered: the WebView presents at most one frame per refresh, so frames beyond it are drawn and thrown away (heat, no smoothness); match display is the fastest real option.

## D63 — Frame-rate independence
**Why:** Ink was tuned and verified at a fixed 1/60 s step; Abdul runs at 165 fps. Audit (Ink + shared engine), each confirmed by measurement (`--dt-sweep`, the same seeded passage at 60/120/165 fps):
1. A hit's ink landed over a fixed 3 frames (drop: 6): 18 ms at 165 fps instead of the tuned 50 ms.
2. The "one-frame push" added velocity for one frame: 2.75× less displacement at 165 fps.
3. The soft advection resamples the ink (bilinear) once per rendered frame, and every resample blurs a little: at 165 fps the ink was blurred about twice as much per second as at 60 (softer, dimmer hits: Glow's median kick rise 47% at 60 fps fell to 39% at 165; Marble's large-shape motion 3.3% → 5.5%; mean brightness +24% in a Glow Flat passage). This existed before the fix too (legacy sweeps show the same).
4. Hits were decided once per rendered frame: a cooldown could expire on a different audio frame at 165 fps, which shifts every later random hit position.
5. The flash guard's running luminance mean advanced by a hard-coded 1/60 s per observed frame (0.22 s time constant at 165 fps instead of 0.6 s).
Harness bug found on the way: offline audio rounded each step to whole samples (1/165 s = 267.27 samples), so audio ran 0.1% slow at 165 fps; it now keeps the fraction.
**Decision:** (1) landing is a time profile with the same shares at 0, 1/60, 2/60 s, linear in between (60 fps lands exactly as before); (2) the push lasts one 60 fps frame of time; (3) the ink is advected in fixed 1/60 s steps (the tuned rate) and the display samples it along the flow by the time since the last step (and fades it as far), so motion stays smooth at any refresh and the ink is resampled exactly as at 60 fps (at 60 fps the result is identical to before; at 165 fps the sim does less work); (4) hits are decided per analysis frame (60 per second of audio); (5) the flash guard uses real time. Everything else (fades, cooldowns, envelopes, camera, auto exposure) was already in seconds. `npm run verify -- --dt-sweep` gates sync, flicker, motion and pop against the 60 fps run so this can't creep back in; it also reports drift (difference of the pictures at equal times), which is informational: sub-frame differences in where a hit lands change the details over seconds without changing the behaviour.

## D64 — Ink hits enter the flow instead of popping in
**Why (measured):** slow-motion evidence shows a highlight blob growing 0 → 4.3% of the frame in 21 ms in empty space. Causes, each checked: the frame-counted landing (D63); the 2nd and 3rd shares landing at the hit's original spot while the 1st had already flowed on (visible as ghosted, triple-stacked bands in Sumi); and a full-size blob simply fading in. Marble's highlight was drawn as a third colour (a mint glow ×2) against D46's duotone intent. Random spawn positions were not changed (v0.1 behaviour; Abdul's timing and composition).
**Decision:** each hit starts as a seed (45% of its radius) on the frame of the hit and spreads to full size (Glow 50 ms so kicks keep their punch, Marble and Sumi 100 ms), carried by the flow while it lands: a CPU copy of the curl field (`flow-field.ts`, same hash and noise as the shader) moves the landing point exactly as the GPU moves the ink already deposited. The ink on screen is always one blob of the current radius and amount: each frame's splat draws only what the new stage adds to the previous one (never negative, so deposits stay additive and the dye cap treats them the same at any frame rate), and the final shape is exactly the old blob's. Marble's highlight lights the marble in its own colours instead of adding a third colour; Marble's hit strength stays 1 (a third, which D46's comment claimed, was measured: no fewer pops, weaker hits). New harness metric: pop score (`ink-metrics.py pop`), new ink unexplained by the flow or by a brightness change, per 1/60 s.

## D65 — Marble's veins are anti-aliased
**Why (measured):** one factor at a time on the same seeded sequence (dye resolution ×2, sharpening off, bilinear / Catmull-Rom / B-spline display filtering, Catmull-Rom sampling of the sim-resolution blurred field, MacCormack vs soft advection, grain off, stipple dither off, veins off): only the veins changed the jaggedness and the fine-detail motion (Marble Depth fine change 11.2% → 5.6% with veins off; every display-sampling factor < 0.1). The veins are `sin(2π·(9·ratio + 4·(blurA − blurB)))`; where the ink ratio is steep (sharp, fast-stretched boundaries, close to the Depth camera) several vein lines fall inside one pixel and alias into dashed, saw-toothed lines that change every frame. Near-camera magnification and dye resolution were not the cause (doubling the dye resolution changed nothing).
**Decision:** where the vein phase changes faster than 0.12–0.3 cycles per pixel (`fwidth`), the veins fade to their average tone; veins wide enough to draw are unchanged. Stills keep the marbled lines; the aliased boundary lines are gone. Sumi has no veins: none of the display factors moved its numbers, and its "breaking" came from the ghosted landing (D64).

## D68 — Palette matrix and colour gates

## D69 — Voyage's stone, nebula and sea carry the palette

## D70 — Wisp's smoke builds up closer to hue-preserving
`1 − exp(−acc)` per channel pulled dense trails of any saturated colour toward grey and white (Ocean 21% grey in Flat, Aurora 22% in Tunnel, the duotones up to 72%). Half is the compromise; the gate already failed here at 1.0.

## D71 — Custom hue, Auto Drift and crossfades in OKLCH; the shade slot
**Why (15° sweep of the custom hue, Auto Drift every 30° from Ocean, Neon and Solar, through the matrix):** turned or picked palettes failed exactly where the presets had: every dark yellow / lime (70–140°) read olive in every style, and mid-light cyans (165–240°) couldn't reach the chroma floor in Marble and Warp (sRGB has no vivid cyan at matched lightness); a ~150° custom accent added up to white with the core in Wisp; Auto Drift bent each colour separately, so its analogous pair straddled the olive band and their blends landed on olive.
**Decision:** `paletteFromHue` builds the presets' structure: primary at full chroma (L 0.60 + a small hue lift toward the gamut cusp), secondary 35° away, accent 70° away on the side whose arc doesn't cross the olive band, highlight leaning to gold (warm) or cyan (cool). The primary skips two bands: olive (65–140° → gold ~66° or lime ~138°) and cyan (162–245° → teal ~160° or azure ~243°, the picked cyan kept as the secondary). Auto Drift turns the palette rigidly and crosses, in 12% of their width of phase, the turns that would rest its primary or secondary in the olive span (70–130°) or its primary in the cyan band; accent and highlight step through the bands on their own (a preset colour resting in a band stays exactly itself at rest). Palette changes crossfade in OKLCH along the shorter hue arc: an RGB crossfade dipped to grey in 6 of 36 preset pairs (Ocean ↔ Solar to chroma 0.008), the OKLCH one never goes below 0.103 (tested). A derived `shade` slot is the primary's dark tone: exactly × 0.55 outside the yellows; golds turn toward amber, yellow-greens stay lighter; Marble on paper uses it for its dark ink (identical for every palette except golds, where it was mustard-olive).
**Result:** every custom hue (24 × 19 combos) passes every colour gate; drift results in the sprint log.

## D83 — Album colours
The palette follows the cover art of what's playing (the media session's thumbnail; on the web, a played file's embedded artwork: ID3 APIC, MP4 `covr`, FLAC PICTURE).
- **Extraction** (`engine/album-palette.ts`): the cover is drawn at 64², clustered in OKLab (k-means, k = 10, deterministic farthest-point start, chroma weighted ×2 in the distance), and the clusters ranked by area × chroma with near-black (L < 0.2), near-white (L > 0.93, C < 0.08) and grey (C < 0.045) left out; vivid clusters within 16° of hue merge (one object in light and shadow); specks under 1.5% are ignored. No vivid colour: a tinted cover (mean chroma ≥ 0.028: sepia, dark duotones) keeps its hue; a grey or black-and-white cover gives nothing.
- **Palette** (`paletteFromCover`): the paletteFromHue structure and rules (matched lightness, full chroma, olive and cyan bands, accent arc clear of olive; tested equal to it for a lone primary outside the olive band) with the cover's hues: primary = the best vivid colour; secondary = a cover colour 18–62° away, else derived; accent = the best-scoring distinct cover hue ≥ 45° away, pulled back to 165° when nearer complementary (Acid's 175° whitened Wisp; Aurora's 157° passes), else derived. Three cover-only refinements, each from the test set: the olive band splits at 118° (a yellow cover reads gold, not lime); an accent on the olive band's edge is allowed when the arc to it doesn't pass through olive (magenta → gold blends through red and orange: Graduation keeps its yellow); a cyan cover accent stays cyan as a light colour (Ocean's accent, L 0.77 C ≤ 0.125, passes every gate) instead of turning azure. Paper stays bone (Sumi).
- **Behaviour:** on a new cover the engine crossfades from what's on screen (drift included) to the album palette in OKLCH along the shorter hue arc over 2.5 s, with the now-playing toast (the brief said OKLab; an OKLab straight line between distant hues dips through grey, D71). The same colours again (next track, same album) change nothing; a cover that vanishes for a moment keeps its colours 4 s. No cover, an advert (Spotify's "Advertisement" / no artist) or a grey cover → the chosen palette. Players that set the cover after the title are asked again for up to 5 s (Rust).
- **Auto Drift** pauses at turn 0 while a cover drives the palette and restarts from the chosen palette when it stops. **Set Mode** never changes palettes while album colours are on (the cover chooses). Picking a preset or custom by hand (picker, keys 1–9) turns album colours off; the Album tile (first in every picker) and the A key turn them on. Album colours are a global setting (the music, not the style).
- **Settings v9:** album colours on for new installs; anyone updating keeps their palette with album colours off and gets a one-time dismissible toast ("new: colours from your album art." · try it). The cover is analysed on the device and never leaves it (said in the (i) card and About).

## D84 — The controller (second screen)
For TV setups: the visual full screen on the TV, a controller window on the laptop as the remote.
- **One source of truth:** the output window owns settings and engine; the controller mirrors the state the output broadcasts and sends calls back (`app/link.ts`, `app/remote-host.ts`). The controller runs the app's own settings sheet and UI kit on a proxy of the Controller and Platform interfaces (`controller/proxy.ts`), so every setting is there without a second implementation. Keys pressed in the controller run the output's shortcuts.
- **Transport:** a BroadcastChannel. Both Tauri windows load the same origin in one WebView2 environment, and the channel was verified between them in `tauri dev`; the same code links two browser tabs (web dev page, screenshots, tests). Covers travel once per cover; the level meter at 12 Hz.
- **Preview:** right after each output frame is drawn (renderer frame hook), every 40 ms of time the canvas is downscaled on the GPU by halving blits to 512 px wide and read into a pixel-pack buffer with readPixels, fenced; a later frame collects it only once the fence has signalled (`clientWaitSync(…, 0)`, never waiting), from a recycled buffer pool; a worker JPEG-encodes it and posts it on its own channel. The output never does a synchronous GPU readback, and the tap runs only while a controller pings (it stops 3.5 s after the controller goes away). Measured: see the sprint log (frame cost, pacing with the tap on, preview fps and latency).
- **Opening:** shortcut R, Settings › Set Mode, the tray ("Controller (second screen)"), and once, automatically, when the visual goes full screen and a second display is there (the controller opens on the other display asking "control sonora from this screen?"). It opens on the display the output isn't on.
- **Safety:** closing the controller changes nothing on the output. A runtime watch (every 2 s, both windows) brings a window that ended up off every display back to the primary one; the output leaves full screen, moves, and goes full screen again there (unplugging the TV).
- **New engine controls** for the remote: glow (bloom × 0.4–1.5 per style; 1 = as designed, gates unchanged at 1), blackout (fades to black and back over 0.4 s, never a cut; analysis and events keep running), freeze (nothing drawn; the canvas keeps its last frame). Set Mode gained "lock to this style" and a calm ↔ driving mood (shifts its music picture by up to ±0.35).
